# Spec Delta

## Purpose

Provides consistent English and Spanish interface localization in the web and mobile apps based on each user's browser or device language, with a predictable fallback for unsupported languages.

## ADDED Requirements

### Requirement: Interface language follows browser or device language
The web and mobile apps SHALL select the interface language from the user's browser or device language automatically and SHALL NOT offer an in-app language switcher.

#### Scenario: Spanish locale is detected
- **WHEN** the browser or device reports Spanish, including a regional Spanish locale
- **THEN** interface text is shown in Spanish

#### Scenario: English locale is detected
- **WHEN** the browser or device reports English, including a regional English locale
- **THEN** interface text is shown in English

#### Scenario: Unsupported locale is detected
- **WHEN** the browser or device reports a language other than English or Spanish
- **THEN** interface text is shown in English

#### Scenario: User cannot override automatic selection in the app
- **WHEN** a user views app settings and navigation
- **THEN** no language switcher or app-level language preference control is presented

### Requirement: Interface copy is available in English and Spanish
All user-facing text rendered inside the web and mobile apps SHALL have English and Spanish translations, including accessibility labels, validation and error messages, and empty, loading, and success states.

#### Scenario: User views a translated screen
- **WHEN** an app screen is rendered in the selected language
- **THEN** its user-facing text and accessibility labels use that language

#### Scenario: A translated message includes dynamic values
- **WHEN** a localized message includes a count, date, number, or user-provided value
- **THEN** the surrounding copy and formatting follow the selected language while the underlying value is preserved

### Requirement: Interface language metadata matches rendered copy
Each app SHALL expose language metadata matching the language used for its rendered interface text.

#### Scenario: Spanish interface is rendered
- **WHEN** an app renders its interface in Spanish
- **THEN** its document or native accessibility language metadata identifies Spanish

#### Scenario: English fallback is rendered
- **WHEN** an app renders English because the device language is unsupported
- **THEN** its document or native accessibility language metadata identifies English

### Requirement: Interface date and number formats follow selected language
Dates and numbers rendered as part of the web or mobile interface SHALL use locale-sensitive formatting consistent with the selected interface language.

#### Scenario: Date is displayed in Spanish
- **WHEN** a screen in Spanish displays a date
- **THEN** the date uses Spanish locale formatting

#### Scenario: Number is displayed in English fallback
- **WHEN** a screen in English displays a number
- **THEN** the number uses English locale formatting

### Requirement: API-generated push notification copy is unchanged
This capability SHALL NOT change the language of notification text generated by the API.

#### Scenario: Push notification is delivered
- **WHEN** the API generates a push notification for a mobile user
- **THEN** the existing API notification copy behavior remains in effect regardless of device language
